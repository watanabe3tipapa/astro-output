## はじめに

CDN 大手から「コネクティビティクラウド」へと姿を変えた Cloudflare は、2026年に入ってさらに次のステージへ進んでいます。その中心にあるのが、AI エージェントの開発・デプロイ・実行を支える **エージェント型クラウド（Agent Cloud）** と、エージェントが経済活動を行うための基盤（**エージェント型インターネット**）です。

本記事では、2026年に発表された Cloudflare の主要サービスを、実行環境・ネットワーク・メール・セキュリティ・コマースの観点からまとめて紹介します。

## 背景 — コネクティビティクラウドからエージェント型クラウドへ

Cloudflare は以前から、グローバルエッジネットワーク上で動作する Workers（サーバーレス）や Durable Objects（ステートフルオブジェクト）を開発者向けに提供してきました。2026年はそれらを「**AI エージェントの実行基盤**」として再編し、一貫したスタックとして提供し始めた年と言えます。

1. **4月** — Agent Cloud の拡張、Cloudflare Mesh、Email Service（パブリックベータ）を発表
2. **8月** — Agents Week 2026 で Wallets や Agents SDK の刷新などを発表
3. **9月** — Adaptive Intelligence、AI クローリング制御の新基準を発表

## Cloudflare Mesh — プライベートネットワーキングの刷新

2026年4月14日、ユーザー・ノード・エージェントすべてを対象としたプライベートネットワーキング **Cloudflare Mesh** が発表されました。

従来は「ユーザー（WARP Client）」「サーバー（Tunnel・Connector）」など用途ごとに異なるツールを組み合わせる必要がありました。Mesh では**単一の軽量コネクタ（単一バイナリ）**で、個人用デバイス、リモートサーバー、エンドポイントのすべてを接続できます。

- ホスト名ルーティング（`wiki.local` や `api.staging.internal` のような名前でアクセス）
- Mesh DNS（後半提供予定）— ノード追加で自動的に `postgres-staging.mesh` 名を解決
- ID ベースのルーティング — IP ではなく「誰が」「何が」接続しているかでポリシーを定義
- Docker イメージ対応（開発中）— Docker Compose にサイドカーを追加するだけでネットワーク参加

既存の Cloudflare One 環境と統合されており、Gateway ポリシーや Access ルール、デバイスポスチャチェックがそのまま適用されます。**最大 50 ノード / 50 ユーザーまで無料**で、ダッシュボードの「Networking > Mesh」から開始できます。

## Workers VPC — Workers からのプライベート接続

Mesh が外部ネットワークを接続する一方、**Workers VPC** は Workers 実行環境側からプライベートネットワークへアクセスするための仕組みです。Mesh と組み合わせることで、Agents SDK で構築したエージェントが Durable Objects からプライベートインフラストラクチャ（自社 DB やバックエンド）へ直接アクセスできます。

```bash
# Agents SDK のインストール
npm i agents
```

## Dynamic Workers — 軽量コード実行ランタイム

エージェントが API 呼び出しやデータ変換のためにコードスニペットを実行するケースは多くあります。従来のコンテナで個別に起動するのはコストがかさみますが、**Dynamic Workers** は分離ベースのランタイムでコードを実行します。

- リクエスト時にミリ秒単位でスピンアップ → JavaScript を実行 → 消滅
- コンテナ比で **約 100 倍高速**、そのわずかなコスト
- ウォームアップ不要で数百万の同時実行までスケール

エージェントの多頻度・短時間のタスクに特化した設計です。

## Cloudflare Sandboxes — サンドボックス型実行環境

8月には、シェル・ファイルシステム・バックグラウンドプロセスを含む永続的な Linux 環境 **Cloudflare Sandboxes** が一般提供（GA）となりました。エージェントはリポジトリのクローン、Python パッケージのインストール、ビルド実行などをセキュアに隔離された環境で行えます。

すでに複数の AI コーディングエージェントプラットフォームとの連携が進んでいます。

| 連携先 | 内容 |
|--------|------|
| Devin Outposts | セキュアな顧客管理環境での実行 |
| Claude Managed Agents | Claude のマネージドエージェントをサンドボックスで実行 |
| Cursor Cloud Agents | Cursor の Self-Hosted Machines をサンドボックスで実行（9月） |

コード・ビルドキャッシュ・シークレットを顧客管理の環境に置いたまま、エージェントループ（推論・計画・オーケストレーション）を外部ツール側が担う、という分担モデルです。

## Cloudflare Email Service — エージェント向けメール

4月16日にパブリックベータへ移行した **Email Service** は、これまで有料・不便だったメール送信を Workers の**ネイティブバインディング**で実現します。API キーやシークレット管理は不要で、ドメイン追加時に **SPF / DKIM / DMARC** が自動設定されます。

注目すべきは「エージェントが郵便受けを扱える」点です。

- Workers / Agents SDK から使える **Email Sending** バインディング
- 受信処理用の **Email Routing**（従来から無料提供）
- **メール MCP サーバー** — エージェントがプロンプトだけでメールを送信・設定
- **Wrangler CLI** のメールコマンド — MCP より軽量（コンテキスト使用量ほぼゼロ）
- **Agentic Inbox** — 受信・分類・送信まで備えたオープンソースのリファレンスアプリ

受信（Email Routing）と送信（Email Sending）が揃ったことで、Cloudflare 上だけで双方向のメール処理が完結します。

## モデルカタログ — Replicate 買収とマルチプロバイダ対応

5月には Replicate の買収が発表され、AI モデルカタログが拡大しています。OpenAI の独自モデルからオープンソースモデルまでを**単一のインターフェース**から呼び出せ、プロバイダの切り替えはほぼ**コード 1 行の変更だけで済みます**。特定ベンダーへのロックインを避けたいエージェント構築者にとって重要です。

## Cloudflare Wallets — エージェントコマースの基盤

8月7日には、エージェントが支払いを行える **Cloudflare Wallets** が発表されました。決済は **Monetization Gateway** が対応する **x402 プロトコル**によるステーブルコインのマイクロペイメントです。

ウォレットは 2 種類に分かれます。

| 種類 | 対象 | 役割 |
|------|------|------|
| Account Wallet | 人間 | 入出金や資金の割り当て |
| Virtual Wallet | エージェント | API キー経由で上限付きの支払いを実行 |

Virtual Wallet には**予算上限・利用可能な販売先・1回あたりの支払い上限**を設定でき、人間が毎回承認しなくても安全な範囲でエージェントがサービスを購入できます。`cloudflare.pay` と連携したエージェント ID の提示にも対応し、マーチャントは「どの組織のエージェントか」を確認できます。

## Adaptive Intelligence — Bot 検知の自動適応

8月31日、Bot Management に組み込まれた新しい検知エンジン **Adaptive Intelligence** が発表されました。

Cloudflare のネットワークを流れる**日々 1 兆件超のトラフィック**から機械学習モデルが自律的に学習し、攻撃者ごとに**有効期間の短いルールを自動生成・入れ替え**します。これにより、防御が常に変化し続け、攻撃者は攻略手法を確立する前に無効化されます。

- 常時稼働する防御 — モデルが継続的に再学習
- 低速・長期型の攻撃（クレデンシャルスタッフィング等）も複数時間軸で検知
- 展開前に実トラフィックでテストし、誤検知を防いでから更新

固定ルールに依存する従来のボット対策とは一線を画す設計です。

## AI クローリング制御 — 検索と学習の分離

9月15日、パブリッシャー向けの AI クローリング制御が刷新されました。従来の「Block AI Bots」スイッチは、以下の 3 つの独立したコントロールに置き換えられています。

1. **検索（search）** — 検索クローラーの許可
2. **AI トレーニング（AI training）** — 学習用クロールの許可
3. **AI エージェント（AI agents）** — エージェントのクロール許可

また、検索を維持したまま学習だけを拒否できる **Disallow AI Training** 設定、Managed Robots.txt を置き換える **Bot Preference Sync**（設定を全クローラーに一括適用）も追加されました。

Apple・Google・Microsoft は「**Accountable**（説明責任を果たす）」指定となり、学習オプトアウト手段の提供や AI 要約のオプトアウト対応などの基準を満たしています。この流れは IETF の **ai-prefs** 仕様（AI アクセス設定の標準化）とも連携します。

## まとめ

2026年の Cloudflare は、単なる CDN やセキュリティ企業から、**AI エージェントが当たり前に動くプラットフォーム企業**へと大きく舵を切りました。

- **実行基盤** — Workers / Dynamic Workers / Sandboxes / Workers VPC
- **接続基盤** — Cloudflare Mesh、Email Service
- **経済基盤** — Wallets / Monetization Gateway（x402）
- **セキュリティ** — Adaptive Intelligence、AI クローリング制御

エージェントの開発・稼働・決済に必要なレイヤーが一つのプラットフォームで揃い始めています。「エージェント型インターネット」への移行期に、Cloudflare は自社ネットワークの規模を武器に、その実行および決済の標準を握ろうとしているのです。

最新情報は [Cloudflare ブログ](https://blog.cloudflare.com/) で確認できます。
