# Astro Output

Publish Markdown as clearly as a GitHub README.

Astro Output is a small technical blog that uses Astro Content Collections and Markdown as the single source of content. Markdown files placed in src/content/posts/ are validated, discovered, rendered to GitHub-style HTML, and published as a static site (the project includes CI workflows to build and deploy to GitHub Pages).

[Open the live site ›](https://watanabe3tipapa.github.io/astro-output/)

[English](README.md) | [日本語](README_ja.md)

## Concept

Astro Output keeps content in Markdown, validates required frontmatter with a Zod schema through Astro Content Collections, renders pages with a GitHub README–like appearance (github-markdown-css), and produces a static site served from GitHub Pages.

## Key features

- Content Collections with a Zod schema validating title, description, and pubDate.
- Automatic discovery of Markdown posts placed under src/content/posts/.
- Static article index and per-article pages generated by the Astro routes (including a dynamic [...slug].astro route).
- GitHub-like Markdown presentation using github-markdown-css and an article element with class="markdown-body".
- Locale and formatting defaults oriented for Japanese readers (document language set to ja and dates formatted with ja-JP locale in the project).
- GitHub Actions workflows that run a production build on pushes and pull requests and deploy the site to GitHub Pages on pushes to main.

## Quick start

Prerequisites

- Node.js >= 22.12.0 (declared in package.json)

Common commands (as provided in package.json)

- Install dependencies: npm ci
- Start dev server: npm run dev
- Build production site: npm run build
- Preview production build locally: npm run preview

Basic local workflow

1. Clone the repository and install dependencies:

   git clone https://github.com/watanabe3tipapa/astro-output.git
   cd astro-output
   npm ci

2. Start the development server:

   npm run dev

   The dev server runs at http://localhost:4321/ by default and reflects changes to Markdown files.

3. Verify a production build locally:

   npm run build
   npm run preview

   npm run build writes static files to dist/ (as described in the project).

## Add and publish an article

- Create a Markdown file under src/content/posts/ with required frontmatter fields (title, description, pubDate).

Example frontmatter:

---
title: "Article title"
description: "A concise summary of the article."
pubDate: 2026-08-22
---

- After adding or updating content, run npm run build to verify the production build locally. When the change is pushed to main, the repository’s GitHub Actions workflows perform a build and, according to the repo configuration, deploy the generated static site to GitHub Pages.

## Technology stack (as declared)

- Framework: Astro ^6.3.1
- Language: TypeScript
- Content validation: Zod (used in Content Collections schema)
- Markdown styling: github-markdown-css
- Runtime: Node.js >=22.12.0
- CI/CD: GitHub Actions and GitHub Pages (workflows present under .github/workflows)

## Project structure (selected)

- .github/workflows/ — CI and deploy workflows (test.yml, deploy.yml)
- src/content/posts/ — Markdown posts (examples included)
- src/content.config.ts — Content Collections and Zod schema
- src/layouts/BlogLayout.astro — shared layout
- src/pages/index.astro — home page
- src/pages/posts/index.astro — article index
- src/pages/posts/[...slug].astro — dynamic article pages
- astro.config.mjs, package.json, README.md, README_ja.md, LICENSE, and other top-level files

## Quality checks and deployment

- Run npm run build locally to verify a production build and Content Collections synchronization.
- GitHub Actions workflows run a production build on pushes to main and on pull requests (test.yml).
- A deploy workflow builds the static site and publishes it to GitHub Pages on pushes to main (deploy.yml).
- When using GitHub Pages for the first time, the repository’s README notes selecting GitHub Actions as the Pages source in the repository settings.
